# Форк HAPI

Это поддерживаемый форк [tiann/hapi](https://github.com/tiann/hapi) для запуска coding-агентов на своих машинах и управления ими из браузера на компьютере или телефоне. В нём сохранены CLI, Hub и Web/PWA HAPI и добавлены инструменты для работы с несколькими проектами, координации агентов и ревью с телефона.

В ветку `custom` влит upstream 0.36.5, поверх него внесены исправления форка. Обзор исходного продукта есть в [README upstream](https://github.com/tiann/hapi#readme), [документации upstream](https://hapi.run/docs/) и [заметках к релизу 0.36.5](https://github.com/tiann/hapi/releases/tag/v0.36.5). Для установки и запуска форка используйте инструкции ниже.

## Что добавляет форк

| Область | Что можно делать |
| --- | --- |
| **Список сессий** | Ищите чаты по проекту, ветке или тексту сообщения. Раздел Working сортируется по вашим действиям, Active и Recent по активности агентов. В Idle могут появляться припаркованные сессии и сессии, от которых приходят только сигналы о подключении. Закрепления, отключение уведомлений для чатов и синхронизация прочитанного через Hub помогают работать с одним списком на компьютере и телефоне. Можно отметить всё прочитанным или удалить HAPI-сессии проекта с сохранением локальной истории агентов. |
| **Проекты и группы** | Ищите, сортируйте и закрепляйте проекты, выбирайте рабочую папку и запускайте один или несколько независимых чатов с общим или отдельными запросами. В именованных группах можно менять порядок вкладок, закреплять их и парковать группу, когда агенты свободны. Поддерживаемые агенты могут находить проекты, запускать других агентов в группах и координировать работу через MCP-инструменты HAPI. |
| **Настройки и управление агентами** | Сохраняйте настройки проектов и моделей, выбирайте глубину рассуждений или скорость, если агент их поддерживает. В Codex доступны Fast и Ultrafast, если их поддерживают выбранная модель и аккаунт. Kimi может использовать модели провайдеров, настроенных в выбранном проекте. Поддерживаемые агенты могут обновлять русские заголовки задач. Ручное переименование защищает заголовок. Сессии можно останавливать, открывать заново и перезапускать из Web/PWA. |
| **Чат и работа с телефона** | Промежуточные вызовы инструментов и рассуждения раскрываются кнопкой **Show work**. На телефоне Enter по умолчанию вставляет новую строку, а черновик сохраняется при переключении между приложениями. На неблокирующие вопросы Codex можно ответить в панели над полем ввода или скрыть их. Когда начинается новый ход, устаревшие вопросы исчезают из панели. |
| **Файлы и ревью** | Ищите среди изменённых файлов или по всему проекту. Смотрите рабочее дерево, последний коммит или изменения ветки относительно автоматически определённой базовой ветки одним diff или по файлам. Правки видны в карточках патчей Codex. Из сессии можно перейти по прикреплённой ссылке на ревью. Сгенерированный HTML открывается в изолированном предпросмотре в браузере. |
| **Мессенджеры** | Подключайте личные аккаунты Telegram или Яндекс Мессенджера на экране **Chats** и выбирайте нужные диалоги. Уведомления Telegram-бота об активности агента ведут прямо в сессию и не приходят, пока открыт и виден именно этот чат. |
| **Расход и лимиты** | В **Settings → Limits** видны лимиты аккаунтов, которые передаёт Runner. Лимиты подписки Claude Code можно обновить по запросу. В **Settings → Usage** владелец Hub видит учтённые токены. Проценты лимитов Cursor рассчитываются приблизительно. |

Подробнее в [документации Web-клиента](web/README.md), [списке агентов](docs/guide/agents.md), [руководстве по взаимодействию сессий](docs/guide/peer-sessions.md) и [документации по расходу и лимитам](docs/guide/usage-and-quotas.md).

## Возможности upstream и ограничения форка

- **Клиенты.** Форк поставляет свой Web/PWA и сохраняет Telegram Mini App. Исходники iOS и Android, сборка, публикация в магазинах и руководство по нативным приложениям намеренно исключены. Часть API для нативных клиентов и поддержка push остаются в Hub. Чтобы открыть интерфейс форка, используйте Web/PWA, который отдаёт ваш Hub. Ссылка для входа и QR-код публичного relay по умолчанию ведут на размещённый у upstream Web-клиент. [Web/PWA](docs/guide/pwa.md) · [Удалённый доступ и собственные туннели](docs/guide/deployment.md)
- **Вход и заголовки.** Для входа в браузере используйте токен Hub. Вход по passkey из upstream в форке недоступен. Если настроен провайдер заголовков, Hub может запросить у него заголовок по команде пользователя. При этом провайдер получает недавний текст беседы. Автоматический запрос из Hub после первого хода отключён по правилам форка. Агенты по-прежнему могут именовать сессии. В меню сессии Codex можно запросить новый заголовок. [Политика синхронизации форка](FORK_SYNC.md)
- **История диалогов.** Совместная сессия в терминале и Web работает с Codex 0.154.0 и новее. Команда upstream `hapi attach` для внешних процессов Codex и создание ветки диалога с выбором другого агента или модели здесь недоступны. Для поддерживаемых агентов в форке есть свои действия для ответвления диалогов. Панель неблокирующих вопросов работает в Web. [Совместные сессии Codex](docs/guide/codex-shared-sessions.md) · [Импорт локальной истории](docs/guide/import-local-sessions.md)
- **Скрытые и убранные функции.** Переключатели Work/Lab/Chill скрыты. В списке видны сессии из всех контекстов, их назначения сохранены. Фильтр по датам находится в раскрытом поиске. Отдельная кнопка «Только непрочитанные» и интеграция DIFIT удалены. Подключение аккаунтов MAX приостановлено, сохранённые аккаунты и история остаются в данных. [Политика синхронизации форка](FORK_SYNC.md) · [Чаты MAX](hub/README.md#max-account-chats-temporarily-disabled)

## Установка и запуск форка

Соберите форк из основной ветки `custom` с Bun 1.4.4. Сборка скачивает вспомогательную программу `tunwg` для relay и встраивает Web-клиент. Отдельно установите хотя бы одного поддерживаемого агента и настройте вход в него.

```bash
git clone --branch custom https://github.com/WarLikeLaux/hapi.git
cd hapi
bun install --frozen-lockfile
bun run build:single-exe
```

Исполняемый файл находится в `cli/dist-exe/<target>/hapi` (`hapi.exe` на Windows). Добавьте его в `PATH` и убедитесь, что команда `hapi` запускает именно эту сборку. Пакет npm `@twsxtd/hapi`, tap Homebrew, готовые релизные файлы и инструкции по обновлению upstream относятся к исходному HAPI.

```bash
hapi hub --no-relay
```

Откройте локальный Web-адрес Hub (по умолчанию `http://127.0.0.1:3006`) и войдите с токеном, который Hub выводит при первом запуске. В другом терминале выполните `hapi` для выбора агента или `hapi codex` для запуска Codex. Чтобы запускать сессии из браузера, запустите Runner на машине с агентом и проектами, например `hapi runner start --workspace-root ~/projects`. На другой машине укажите тот же адрес Hub и токен доступа. [Конфигурация](docs/guide/configuration.md) · [CLI и Runner](cli/README.md) · [Уведомления](docs/guide/notifications.md)

### Обновление установленного форка

В рабочей копии форка на ветке `custom` выполните `git pull --ff-only origin custom`, затем повторите установку зависимостей и сборку. Замените установленный файл и обновите Hub, Runner и CLI на всех машинах вместе. Перед обновлением сделайте резервную копию данных Hub. Runner умеет переключаться на совместимый исполняемый файл, который вы установили локально.

Если Hub уже работает как пользовательский сервис systemd в Linux, выполните `bun run deploy:local-hub` из основной рабочей копии на ветке `custom`. Помимо Bun нужен Go 1.25 или новее. Скрипт собирает и устанавливает HAPI и коннектор Telegram, сохраняет предыдущие исполняемые файлы и перезапускает Hub. По умолчанию он также проверяет типы и запускает тесты Hub. Если сервис Runner существует, скрипт закрепляет установленный файл для следующих запусков и перезапускает активный Runner только при `KillMode=process`. По умолчанию используются `hapi-hub.service`, `hapi-runner.service` и `~/.local/lib/hapi-custom/current/hapi`. Для своей конфигурации задайте `HAPI_SERVICE_NAME`, `HAPI_RUNNER_SERVICE_NAME` или `HAPI_INSTALL_PATH`. В `ExecStart` сервиса Hub уже должен стоять путь установки. [Скрипт развёртывания](scripts/deploy-local-hub.sh)

### Подключение личных чатов

Для Telegram соберите MTProto-коннектор командой `bun run build:telegram-connector` (Go 1.25 или новее). Поместите `connectors/telegram/hapi-telegram-connector` рядом с установленным исполняемым файлом HAPI. На Windows добавьте к имени коннектора расширение `.exe`. Скрипт развёртывания в Linux делает это сам. В разделе **Chats** введите API ID и hash, затем пройдите вход по телефону, коду и паролю 2FA, если он настроен. Яндекс Мессенджер использует cookies авторизованного аккаунта. Данные для входа в оба коннектора храните как секреты аккаунтов. Hub кэширует выбранные вами диалоги. Для уведомлений бот использует свой токен. [Руководство по коннектору Telegram](connectors/telegram/README.md) · [Ключи API Telegram](https://my.telegram.org/apps)

## Локальная разработка

Клонируйте репозиторий и установите зависимости, как описано выше. Для сервера разработки Web также нужен Node.js 22.12 или новее. Из корня репозитория запустите Hub и Vite с отдельным каталогом данных для разработки.

```bash
export HAPI_HOME="$HOME/.hapi-dev"
bun run dev
```

Откройте адрес Vite из терминала и войдите с токеном Hub для разработки. По умолчанию Vite направляет запросы API в Hub на порту 3006. Если порт занят другим Hub, перед запуском задайте `HAPI_LISTEN_PORT` и укажите соответствующий локальный адрес в `VITE_HUB_PROXY`. Чтобы запустить CLI из исходников с этим Hub, укажите тот же `HAPI_HOME` в другом терминале и выполните `bun run --cwd cli dev codex`. Если меняли порт, задайте там и `HAPI_API_URL`. [Участие в разработке](CONTRIBUTING.md) · [Разработка Hub](hub/README.md#running) · [Разработка Web](web/README.md#development) · [Pitbox и предпросмотр интерфейса](scripts/tooling/README.md)

## Безопасность и сопровождение

- Проверяйте режим разрешений при создании сессии Codex в Web. В новой форме запуска Codex по умолчанию выбран YOLO. YOLO отключает песочницу агента и обычные подтверждения вызовов инструментов. Явные запросы из execpolicy и MCP-сценарии, которым нужен ваш ввод, могут по-прежнему появляться.
- Явно заданные рабочие корни Runner ограничивают выбор папок и запуск сессий. Без них поиск папок ограничивается домашним каталогом пользователя Runner, а при ручном запуске доступны и другие разрешённые этому пользователю пути. Рабочие корни и разрешения песочницы агента настраиваются отдельно.
- Держите токены, данные для входа в мессенджеры и настройки конкретных машин вне Git. Для удалённого доступа настройте аутентификацию и HTTPS. Для Telegram Mini App укажите его публичный HTTPS-адрес в `HAPI_PUBLIC_URL`. [Политика безопасности](SECURITY.md) · [Пространства имён](docs/guide/namespace.md) · [Удалённый доступ](docs/guide/deployment.md)

Сопровождающие проверяют изменения из `upstream/main` и вливают их в `custom` настоящим merge-коммитом с `--no-ff`. В CI форка выполняется **Test**, а **fixtures** проверяется при изменении соответствующих путей. Сохраняйте ограничения CI и историю слияний без rebase и force-push. Для публикации, подписания и развёртывания требуется отдельное разрешение. [Политика синхронизации форка](FORK_SYNC.md) · [Правила репозитория](AGENTS.md)
