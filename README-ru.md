# Пользовательский форк HAPI

Это поддерживаемый форк [HAPI](https://github.com/tiann/hapi) для локального Codex-процесса, которым можно управлять из терминала на компьютере и с телефона через Web/PWA. Он сохраняет архитектуру upstream — агенты, Hub, Web/PWA и Telegram — и меняет навигацию по сессиям, запуск проектов и уведомления.

Полное описание продукта, поддерживаемых агентов и архитектуры находится в **[каноническом README upstream](https://github.com/tiann/hapi#readme)**. Здесь перечислены только отличия и правила эксплуатации этого форка.

## Что изменено в форке

| Область | Поведение форка | Практический результат |
| --- | --- | --- |
| Навигация по сессиям | Отдельные разделы Working, Active и Recent; стабильная сортировка по активности; непрочитанные ответы; закрепление внутри проекта и глобально; скрытие неактивных сессий; подписи проекта и Git-ветки; массовое удаление HAPI-сессий проекта с сохранением локальных транскриптов агента. | Нужные сейчас сессии остаются на виду с понятным контекстом проекта, а старые не забивают список. |
| Проекты и новые сессии | Поиск, сортировка и закрепление корней рабочих пространств, ручной выбор папки, Codex первым в списке и первый настроенный корень как начальная директория. | Runner, ограниченный общей папкой с проектами, позволяет запускать Codex в любом разрешённом проекте без жёстко заданных путей. |
| Файлы и проверка Git-изменений | На экране Files поиск среди изменённых файлов отделён от поиска по всему проекту. Можно посмотреть рабочее дерево, последний коммит или текущую ветку относительно автоматически определённой базовой ветки — по отдельным файлам либо одним полным diff. | С телефона видны и незакоммиченные правки, и полный результат работы в ветке без необходимости открывать каждый файл отдельно. |
| Настройки Codex и жизненный цикл | Новые сессии Codex изначально используют YOLO; последующий явный выбор запоминается. Stop, reopen, restart и синхронизация истории Codex аккуратнее сохраняют состояние и время активности. Codex поддерживает русские заголовки задач в соответствии с текущей целью, а меню сессии позволяет запросить их перегенерацию. | Работу можно начать быстрее, проще переключаться между HAPI и локальной сессией Codex, а назначение длинных диалогов остаётся понятным. **YOLO отключает песочницу и обычные подтверждения вызовов инструментов, но явные execpolicy-правила `prompt` и MCP-сценарии, требующие ввода пользователя, по-прежнему показываются через HAPI.** |
| Чат и мобильный интерфейс | Промежуточные рассуждения и вызовы инструментов собраны под одной кнопкой `Show work`. Enter на телефоне добавляет новую строку, кнопка отправки удобнее для касания, а зависшее состояние PWA/SSE восстанавливается надёжнее. HTML-файлы, переданные через HAPI, открываются в новой вкладке браузера в изолированном preview без обязательного предварительного скачивания. | Транскрипт компактнее, ввод с телефона похож на обычный мессенджер, а созданные схемы и отчёты открываются одним нажатием без доступа к авторизованному origin HAPI. |
| Telegram | Уведомления содержат прямую ссылку на сессию и не отправляются только тогда, когда на экране открыт именно этот чат. | На странице списка, в другом чате или в фоне уведомления продолжают приходить, но открытый чат не дублируется. |
| Поддержка и релизы | Upstream проверяется и вливается в `custom` настоящим merge-коммитом. Синхронизация не разрешает публикацию, подпись, деплой или force-push. | Функции форка и границы безопасности проверяются, а не перезаписываются обновлениями upstream. |
| Клиенты | Проекты upstream `ios/` и `android/`, их CI/release-workflow и инструкция по сборке нативных приложений намеренно удалены. | Форк использует только Web/PWA и не скачивает и не собирает мобильные SDK-проекты. |

Главное эксплуатационное отличие — способ распространения: npm-пакеты, релизные бинарники и автообновление upstream устанавливают upstream HAPI, а не этот форк. Инструкции upstream для сборки нативных приложений здесь неприменимы.

## Установка и запуск форка

Ветка по умолчанию — `custom`. Для сборки из исходников нужен Bun 1.4.0:

```bash
git clone --branch custom YOUR_FORK_CLONE_URL hapi
cd hapi
bun install --frozen-lockfile
bun run build:single-exe
```

Замените `YOUR_FORK_CLONE_URL` адресом из меню **Code** этого репозитория. Не используйте `npx @twsxtd/hapi` или релизные бинарники upstream, если ожидаете описанное выше поведение форка. Механизм смены версии runner умеет активировать установленный вами бинарник форка, но сам обновления форка не скачивает.

Для уже настроенной Linux-установки через пользовательские службы systemd в репозитории есть защищённая команда локального деплоя:

```bash
bun run deploy:local-hub
```

Она проверяет типы и тесты Hub, собирает встроенный веб-клиент и исполняемый файл, сохраняет предыдущий бинарник для отката, перезапускает Hub и настраивает будущие запуски runner на тот же бинарник форка. По умолчанию ожидаются `hapi-hub.service`, `hapi-runner.service` и `~/.local/lib/hapi-custom/current/hapi`; их можно изменить через `HAPI_SERVICE_NAME`, `HAPI_RUNNER_SERVICE_NAME` и `HAPI_INSTALL_PATH`. Перед использованием на другом компьютере прочитайте [скрипт деплоя](scripts/deploy-local-hub.sh).

Общие инструкции upstream остаются применимы: [установка и переменные окружения](docs/guide/installation.md), [агенты](docs/guide/agents.md), [Web/PWA](docs/guide/pwa.md) и [уведомления](docs/guide/notifications.md).

## Безопасность и приватная конфигурация

- Не добавляйте в Git токены Hub, Telegram-бота, публичные или приватные адреса, а также локальные пути.
- Просмотр рабочих пространств ограничен корнями, явно переданными через `hapi runner start --workspace-root <путь>`; без них доступна только домашняя папка пользователя runner, а не вся файловая система.
- Считайте YOLO опасным режимом: он обходит обычные подтверждения и ограничения песочницы агента, кроме явных execpolicy-правил `prompt` и MCP-сценариев, требующих реального ввода пользователя.
- Публикация Hub или включение Telegram по-прежнему требует аутентификации, TLS, туннеля и корректного `HAPI_PUBLIC_URL` по документации upstream. Локальный деплой сам по себе не делает публичный Hub безопасным.

Перед изменением аутентификации, пространств имён, исполнения команд, уведомлений, доступа к файлам, управления runner, внешних ссылок или релизных workflow прочитайте [SECURITY.md](SECURITY.md) и [политику синхронизации форка](FORK_SYNC.md).

## Обновление из upstream

Постоянные правила записаны в [FORK_SYNC.md](FORK_SYNC.md). Кратко: изменения из `upstream/main` проверяются и вливаются в `custom` через `--no-ff`; функции форка, границы безопасности, ограничения релизных workflow и тесты должны сохраниться. Поддерживаемую ветку нельзя перебазировать или публиковать через force-push.

## Лицензия и благодарности

HAPI означает «哈皮» — китайскую транслитерацию названия [Happy](https://github.com/slopus/happy). Исходный проект HAPI и его участники остаются авторами продукта; этот репозиторий поддерживает специализированную downstream-адаптацию.
